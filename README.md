# فرهنگسرای سیمرغ

اپلیکیشن اندرویدی مبتنی بر HTML/CSS/JS و Capacitor، همراه با API مبتنی بر Express و PostgreSQL.

## وضعیت این شاخه

این شاخه برای هماهنگی API با دیتابیس جدید سیمرغ ساخته شده است. سرور از ساختار موجود استفاده می‌کند و هنگام شروع، هیچ فایل SQL یا عملیات ساخت/حذف جدول اجرا نمی‌کند.

- جدول‌های دیتابیس توسط ساختار فعلی PostgreSQL مدیریت می‌شوند.
- نقش‌ها و مجوزها از `roles`، `permissions`، `user_roles` و `role_permissions` خوانده می‌شوند.
- کافه فقط نمایش منو است و سفارش آنلاین کافه ندارد.
- خرید کتاب و محصولات فروشگاه به شکل درخواست خرید حضوری ثبت می‌شود.
- شروع دوره امانت در لحظه تحویل واقعی کتاب ثبت می‌شود؛ مهلت اولیه ۷ روز است.
- امتیاز مثبت رویداد فقط بعد از ثبت حضور صادر می‌شود.
- فایل `server/schema.sql` متعلق به نسخه قدیمی است؛ روی دیتابیس جدید اجرا نشود.

## استقرار روی چابکان

تنظیمات سرویس Node.js:

- Root Directory: `server`
- Node.js: نسخه 20 یا جدیدتر
- Install Command: `npm install`
- Start Command: `npm start`

متغیرهای محیطی لازم:

- `DATABASE_URL`: رشته اتصال PostgreSQL
- `JWT_SECRET`: مقدار تصادفی محرمانه حداقل ۳۲ کاراکتر
- `PORT`: در صورت نیاز؛ معمولاً چابکان آن را تنظیم می‌کند.
- `DB_SSL`: مقدار `true` فقط اگر سرویس دیتابیس SSL می‌خواهد؛ در غیر این صورت `false`.

از ثبت `.env`، رمز دیتابیس یا JWT در GitHub خودداری کنید.

پس از Deploy، آدرس زیر را بررسی کنید:

```
https://YOUR-API-DOMAIN/api/health
```

پاسخ سالم:

```json
{"ok":true,"database":true,"version":"db-compatible-1"}
```

## مدیر کردن حساب

1. ابتدا کاربر از داخل اپ ثبت‌نام کند.
2. در محیط سرور، از پوشه `server` اجرا کنید:

```bash
npm run make-admin -- 09123456789
```

این دستور نقش مدیر را از طریق جدول واسط `user_roles` اضافه می‌کند؛ ستون قدیمی `users.role` استفاده نمی‌شود.

## آدرس API در APK

فایل `www/config.js` آدرس API را نگه می‌دارد. در صورت تغییر دامنه چابکان، مقدار `API_BASE` را به نشانی جدید به همراه `/api` تغییر دهید و APK را دوباره بسازید.

## هشدار درباره db:init

دستور `npm run db:init` عمداً غیرفعال شده است؛ فایل SQL قدیمی این مخزن با دیتابیس فعلی سازگار نیست. برای راه‌اندازی این نسخه، آن را اجرا نکنید.

## موارد نیازمند تکمیل و آزمون عملی

- آزمون کامل رابط کاربری و API روی دیتابیس واقعی و حساب‌های آزمایشی
- فرم مدیریت نسخه‌های قوانین رویداد و تعیین امتیاز هر رویداد
- تعیین مبلغ جریمه لغو پس از شروع رویداد؛ مبلغ آن هنوز مشخص نشده است.
- اجرای زمان‌بندی‌شده جریمه دیرکرد امانت و سیاست تعلیق پس از مهلت مقرر
- فرم مدیریتی حضور و غیاب؛ API ثبت حضور آماده شده، اما دکمه مدیریتی آن هنوز به رابط کاربری افزوده نشده است.
- تکمیل گزارش‌ها، مدیریت نقش‌ها و مدیریت رسانه‌ها

این شاخه را قبل از استقرار نهایی باید در محیط آزمایشی بررسی کرد؛ صرف ساخته‌شدن commit به معنی تأیید عملکرد روی دیتابیس واقعی نیست.
